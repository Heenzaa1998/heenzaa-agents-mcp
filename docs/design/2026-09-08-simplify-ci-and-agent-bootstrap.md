# ลด CI เหลือ quality gate, ลบ Gitea, เพิ่ม CLAUDE.md

- **วันที่:** 2026-09-08
- **สถานะ:** implemented
- **Change record:** `docs/changes/2026-09-08-simplify-ci-and-agent-bootstrap.md`
- **ต่อจาก:** `docs/design/2026-09-08-github-actions-and-docs.md`

## ปัญหา

หลังพอร์ต CI ขึ้น GitHub Actions รันแรกออกมาว่า `validate`, `preflight`,
`quality` ผ่าน แต่ job `image` ถูก cancel — และในทางปฏิบัติ job นั้นก็ไม่มี
ประโยชน์อยู่แล้วเพราะ repo นี้ไม่ได้ deploy ผ่าน Harbor/MiniIDP บน GitHub
เจ้าของ repo ยืนยันว่าต้องการแค่ quality gate

ประเด็นที่สอง: `.gitea/` ไม่ได้ใช้แล้ว แต่ยังค้างอยู่และทำให้สับสนว่า
CI ตัวไหนคือตัวจริง

ประเด็นที่สาม: `AGENTS.md` มีกติกาครบแต่ยาว agent ที่เข้ามาใหม่มักเริ่มแก้ไฟล์
ก่อนอ่านบริบท ทำให้ถามคำถามที่ repo ตอบได้อยู่แล้ว หรือลงมือโดยไม่รู้ว่า
งานล่าสุดคืออะไร

## ขอบเขต

**อยู่ในขอบเขต:**
- ตัด CI เหลือ job `quality` job เดียว
- ลบ `.gitea/` ทั้งโฟลเดอร์
- เพิ่ม `CLAUDE.md` เป็นไฟล์ปฐมนิเทศที่ชี้ไป `AGENTS.md`

**ไม่อยู่ในขอบเขต:**
- ย้ายเนื้อหา `AGENTS.md` มาไว้ใน `CLAUDE.md` — `AGENTS.md` ยังเป็นแหล่งความจริงเดียว
- เพิ่ม `pnpm test` / `pnpm e2e` เข้า CI (ยังค้างอยู่ในรายการตามมาทีหลัง)

## ทางเลือกที่พิจารณา (CLAUDE.md)

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| A: symlink ไป AGENTS.md | ไม่มีเนื้อหาซ้ำเลย | ไม่ได้เพิ่มอะไร agent ยังไม่รู้ว่าต้องอ่านอะไรก่อน |
| B: คัดลอกกติกามาไว้ทั้งหมด | agent อ่านไฟล์เดียวจบ | เนื้อหาซ้ำสองที่ แตกต่างกันเมื่อแก้ที่เดียว |
| C: ไฟล์สั้นที่เป็น "ลำดับการอ่าน" + ชี้ไป AGENTS.md | ไม่ซ้ำ, บังคับให้ agent มีบริบทก่อนตอบข้อความแรก | ต้องระวังไม่ให้บวมจนกลายเป็น B |

## ทางที่เลือก

เลือก **C** โครงของ `CLAUDE.md` คือ:

1. **ลำดับการอ่านก่อนตอบข้อความแรก** — อ่าน `AGENTS.md` ให้จบ, อ่าน `package.json`
   เพื่อรู้ชื่อโปรเจกต์/stack/scripts (ย้ำว่าชื่อโฟลเดอร์ไม่ใช่แหล่งความจริง
   `package.json` ต่างหาก), อ่าน `docs/README.md` แล้วไล่ `docs/changes/` กับ
   `docs/design/` ล่าสุด 2–3 อัน, แล้วดู `git log` + `git status`
2. **วิธีเปิดบทสนทนา** — สรุปสิ่งที่เข้าใจเป็นบรรทัดเดียว แล้ว *เสนอ* ถ้าโจทย์ชัดพอ
   หรือ *ถาม* เฉพาะคำถามที่ถ้าตอบต่างกันแล้วงานออกมาต่างกันจริง
   ห้ามเปิดด้วย "อยากให้ทำอะไรครับ" ทั้งที่ผู้ใช้บอกมาแล้ว
3. **ข้อห้ามที่ agent มักข้าม** — design first, บันทึก docs, ใช้ pnpm, รัน `pnpm check`
4. **ตารางชี้ทาง** — คำถามแบบไหน ไปอ่านไฟล์ไหน

จุดสำคัญคือข้อ 1 และ 2 ที่ทำให้ agent มีบริบทตั้งแต่ข้อความแรก
ตามที่เจ้าของ repo ต้องการ

  และดึงไฟล์เก่าจาก git history ได้
- แผนถอยกลับ: `git revert` หรือ `git checkout <sha> -- .gitea`
