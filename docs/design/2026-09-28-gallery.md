# หน้า gallery รูป/วิดีโอ ล็อกด้วยรหัสผ่านเดียว

- **วันที่:** 2026-09-28
- **สถานะ:** approved
- **Change record:** `docs/changes/2026-09-28-gallery.md` (เติมเมื่อทำเสร็จ)

## ปัญหา

ประวัติงาน (`generations`) และไฟล์ใน R2 ดูได้จากแชทผ่าน MCP เท่านั้น ผู้ใช้อยากเปิดดูงานทั้งหมด
ในหน้าเว็บ แต่หน้าเว็บของ template เป็น public และประวัติมี prompt กับไฟล์ส่วนตัว จึงต้องล็อก

## ขอบเขต

**อยู่ในขอบเขต:**
- `/gallery`: รายการงานล่าสุด แสดงรูป/วิดีโอ, prompt, สถานะ, เวลา, key; filter ประเภท/สถานะ/คำค้น
- ปุ่มเช็คสถานะวิดีโอที่ยัง `pending` (เรียก `getTaskStatus` เดิม)
- `/gallery/login` + ออกจากระบบ ด้วยรหัสผ่านเดียวจาก env `GALLERY_PASSWORD`
- session เป็น cookie ที่เซ็นด้วย HMAC (ไม่เพิ่ม dependency)
- เมนู Gallery ใน header/footer และรายการใน `liveRoutes`
- unit tests ของ session และ service

**ไม่อยู่ในขอบเขต:**
- บัญชีผู้ใช้หลายคน (Neon Auth), ลืมรหัสผ่าน, จำกัดจำนวนครั้งที่ login ผิดแบบมี state
- สร้าง/ลบงานจากหน้าเว็บ
- pagination (แสดงล่าสุดสูงสุด 30 รายการ)

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| A: รหัสผ่านเดียว + cookie เซ็น HMAC | ไม่มี dependency, ใช้คนเดียวพอดี, ทำเสร็จเร็ว | ไม่มีบัญชีแยกคน, กัน brute force ได้แค่หน่วงเวลา |
| B: Neon Auth | บัญชีจริง, OAuth | ต้องเพิ่ม SDK, ตาราง users, หน้า sign-in เกินความจำเป็นของผู้ใช้คนเดียว |
| C: Vercel Deployment Protection | ไม่ต้องเขียนโค้ด | ล็อกทั้งเว็บรวมถึง `/api/mcp` ที่ claude.ai ต้องเข้า |

ผู้ใช้เลือก A

## ทางที่เลือก

- **ไม่ตั้ง `GALLERY_PASSWORD` = gallery ปิด (fail-closed)** ต่างจาก MCP token ที่ไม่ตั้ง = เปิด
  เพราะหน้านี้โชว์ prompt และไฟล์ส่วนตัว
- cookie `gallery_session` = `<หมดอายุ ms>.<HMAC-SHA256>` key ของ HMAC สร้างจากรหัสผ่าน
  (เปลี่ยนรหัสผ่าน = session เก่าหมดอายุทันที ไม่ต้องมี secret ตัวที่สอง) อายุ 30 วัน,
  `httpOnly`, `sameSite=lax`, `secure` บน production, `path=/gallery`
- เทียบรหัสผ่านด้วย `timingSafeEqual` บน SHA-256; ใส่ผิดหน่วง 1 วินาที
- **ตรวจ session ทั้งในหน้าและใน server action ทุกตัว** (server action เรียกตรงได้ ไม่ผ่านหน้า)
- ลิงก์รูป/วิดีโอบนหน้าเป็น presigned อายุ 1 ชม. สร้างตอน render ไม่เรียก HEAD ทีละไฟล์
- ใช้ `<img>` / `<video>` ตรง ๆ (ลิงก์ presigned เปลี่ยนทุกครั้ง ผ่าน image optimizer ไม่คุ้ม)
- หน้า `force-dynamic` + `noindex`

## ความเสี่ยง / ผลกระทบ

- **ผลต่อ schema:** ไม่มี
- **ผลต่อ API contract:** ไม่มี (เพิ่มหน้าเว็บและ server action)
- **ผลต่อ observability:** ไม่แตะ span chain; หน้าเรียก service ที่มี span อยู่แล้ว
- **ความปลอดภัย:** รหัสผ่านอ่อน = เดาได้ ต้องใช้รหัสยาวสุ่ม; ไม่มี lockout มีแค่หน่วงเวลา
- **ค่า R2:** เปิดหน้า 1 ครั้ง presign ได้โดยไม่เรียก R2 (เซ็นในเครื่อง) มีค่าเฉพาะตอนเบราว์เซอร์โหลดไฟล์
- **แผนถอยกลับ:** ลบ env `GALLERY_PASSWORD` (gallery ปิด) หรือ revert commit
