# หน้า gallery รูป/วิดีโอ ล็อกด้วยรหัสผ่านเดียว

- **วันที่:** 2026-09-28
- **Design doc:** `docs/design/2026-09-28-gallery.md`
- **Commit / PR:** branch `feat/gallery`

## เปลี่ยนอะไร

เพิ่มหน้า `/gallery` แสดงงานรูป/วิดีโอจากตาราง `generations` (ลิงก์ presigned 1 ชม.) พร้อม filter
ประเภท/สถานะ/คำค้น และปุ่มเช็คสถานะวิดีโอที่ยังค้าง ล็อกด้วยรหัสผ่านเดียว (`GALLERY_PASSWORD`)
ผ่านหน้า `/gallery/login` และ cookie ที่เซ็นด้วย HMAC เพิ่มเมนู Gallery ใน header/footer

## ทำไม

ประวัติงานดูได้แค่ผ่านแชท ผู้ใช้อยากเปิดดูทั้งหมดในหน้าเว็บ แต่ template เป็น public จึงต้องล็อก

## ต่างจากแผนตรงไหน

- ไม่ได้ทำหน้า "ยังไม่ได้ตั้งค่า" แยก: `/gallery` เด้งไป `/gallery/login` ทุกกรณีที่เข้าไม่ได้
  และหน้า login บอกเองว่า `GALLERY_PASSWORD` ยังไม่ถูกตั้ง
- **backfill ประวัติ 5 แถว** ลง `generations` (รูป 3, วิดีโอ 2) สำหรับงานที่สร้างก่อนระบบบันทึก
  มีอยู่ ใช้ prompt/model/task id จริง และเช็คแล้วว่าไฟล์ใน R2 ยังอยู่ครบ (ทำตรงลง DB ไม่ได้อยู่ในโค้ด)

ผลลัพธ์ / สิ่งที่ยังค้าง:
- ทดสอบด้วย Chromium จริงบน dev: ไม่มี session → หน้า login; รหัสผิด → "Wrong password." หลังหน่วง
  ~1.4s; รหัสถูก → gallery แสดงรูป 4/4 โหลดได้ และวิดีโอ 2; cookie `httpOnly`, `path=/gallery`,
  `SameSite=Lax`, อายุ 30 วัน; filter วิดีโอได้ 2 คลิป 0 รูป; ออกจากระบบแล้วเข้าไม่ได้; cookie ปลอม
  (อายุยาว + ลายเซ็นมั่ว) ถูกปฏิเสธ
- เทสหน้า Operations (`site-pages.test.tsx`) timeout เป็นบางรอบ เป็นอาการเดิมที่เกิดบน `main`
  ด้วย ไม่เกี่ยวกับงานนี้
- บั๊กเดิมของ template: เมนูที่ active มีสีตัวอักษรเท่ากับสีพื้น (มองไม่เห็นชื่อ) เป็นทุกหน้า
- ตั้ง `GALLERY_PASSWORD` บน Vercel production + preview แล้ว ยืนยันบน production หลัง merge

## ตามมาทีหลัง
