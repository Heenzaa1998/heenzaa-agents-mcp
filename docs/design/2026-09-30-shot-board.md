# Shot board: ตรวจงานทีละช็อตบนหน้าโปรเจกต์

- **วันที่:** 2026-09-30
- **สถานะ:** approved
- **Change record:** `docs/changes/2026-09-30-shot-board.md` (เติมเมื่อทำเสร็จ)

## ปัญหา

หน้า `/projects/[id]` แสดง take ของแต่ละช็อตเป็นการ์ดเรียงกัน ภาพและวิดีโอปนกัน ไม่รู้ว่าวิดีโอ take ไหน
สร้างจากภาพเฟรมแรก/เฟรมสุดท้ายภาพไหน และตรวจความผิดพลาดในวิดีโอ (หางยาว กิ๊บสลับข้าง) ต้องดึงเฟรม
ด้วยสคริปต์ในเครื่องแล้วส่งภาพให้เจ้าของงานดู เจ้าของงานตรวจเองบนมือถือไม่ได้

## ขอบเขต

**อยู่ในขอบเขต:**
- บันทึก **inputs** ของทุก generation (คอลัมน์ `inputs` jsonb, string[]): ภาพต้นทางของ `edit_image`
  และ `image_url` / `end_image_url` / ภาพของ elements ของ `generate_video` เก็บเป็น storage key เมื่อชี้มาที่
  bucket ของเรา (แปลง presigned URL กลับเป็น key) ไม่งั้นเก็บ URL ตามที่ให้มา
- หน้าโปรเจกต์จัดเป็น **shot board**: ช็อตเรียงตามชื่อแบบธรรมชาติ (S01…S12) แต่ละช็อตแยกแถว
  "ภาพ" (keyframes เป็น thumbnail) และ "วิดีโอ" (take cards) การ์ดวิดีโอแสดงภาพต้นทางที่ใช้ (จับคู่จาก
  inputs กับ media key ของภาพในโปรเจกต์)
- **ตัวตรวจเฟรม** (client component): เลื่อนวิดีโอทีละ 0.5 วินาที, เล่น/หยุด, ซูม 2 เท่าและเลือกมุม,
  และ "แถบเฟรม" 8 ช่องที่ใช้ `<video src="…#t=…">` (media fragment) โดยไม่ต้องใช้ ffmpeg หรือ CORS
- ส่วน **ต้นแบบ** ของโปรเจกต์ (จาก `reference_images`) แสดงเป็น thumbnail พร้อม key

**ไม่อยู่ในขอบเขต:**
- สร้าง poster/เฟรมฝั่ง server (ไม่มี ffmpeg บน Vercel)
- แก้ไขหรือสั่งเจนจากหน้าเว็บ

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| A: media fragment `#t=` หลาย `<video>` + ตัวเลื่อนเฟรม (client) | ไม่ต้อง CORS/ffmpeg ทำได้เลย | โหลดวิดีโอซ้ำหลายครั้งต่อ take (เปิดเมื่อกดเท่านั้น) |
| B: canvas จับภาพจากวิดีโอ | เบา ได้ภาพนิ่งจริง | ต้องตั้ง CORS ที่ R2 bucket และเก็บผลไม่ได้ |
| C: ดึงเฟรมฝั่ง server แล้วเก็บ R2 | ตรวจได้จาก thumbnail เลย | Vercel ไม่มี ffmpeg |

## ทางที่เลือก

**A** — แถบเฟรมเปิดตามต้องการ (ปุ่ม) จึงไม่โหลดทุก take พร้อมกัน ตัวเลื่อนใช้ `<video>` ตัวเดียว
- inputs ที่ให้มาเป็น URL ของ bucket เรา จะ normalize เป็น key ตอนบันทึก เพื่อจับคู่กับภาพในโปรเจกต์ได้
  (`toStoredKey` ใน feature media)
- การเรียง: แยกตัวอักษรกับตัวเลขในชื่อช็อต (`localeCompare` แบบ numeric)

## ความเสี่ยง

- Safari บางรุ่นไม่แสดงเฟรมจาก `#t=` จนกว่าจะเริ่มโหลด ใช้ `preload="auto"` และ `muted playsInline`
- take เก่าที่บันทึกก่อนมีคอลัมน์ inputs จะไม่มีภาพต้นทาง (ค่าเริ่มต้น `[]`) ยอมรับได้

## การทดสอบ

- unit: `toStoredKey` (presigned URL ของ bucket → key, URL อื่นคงเดิม), service image/video บันทึก inputs,
  การเรียงช็อตแบบธรรมชาติ, i18n มี key ครบสองภาษา
- dev + Playwright: หน้าโปรเจกต์แสดงแถวภาพ/วิดีโอ ต้นแบบ และเปิดแถบเฟรมได้ ไม่มี error ใน console
