# edit_image ใช้ GPT Image 2 และรองรับสัดส่วนภาพทุกแบบ

- **วันที่:** 2026-09-28
- **สถานะ:** approved
- **Change record:** `docs/changes/2026-09-28-edit-image-gpt-image-2.md` (เติมเมื่อทำเสร็จ)

## ปัญหา

`edit_image` ใช้ `gpt-image/1.5-image-to-image` ซึ่งรองรับแค่ 1:1, 2:3, 3:2
งานวิดีโอแนวตั้ง (TikTok 9:16) ต้องทำภาพ keyframe จากภาพอ้างอิงตัวละคร ภาพจึงต้องออกเป็น 2:3
แล้วครอปเสียขอบ ตอนนี้ KIE มี `gpt-image-2-image-to-image` แล้ว รองรับสัดส่วนภาพและความละเอียด
ชุดเดียวกับ `generate_image` (รุ่นเดียวกัน)

## ขอบเขต

**อยู่ในขอบเขต:**
- `edit_image` ใช้ GPT Image 2 เป็นค่าเริ่มต้น: สัดส่วนภาพ 16 แบบ (รวม 9:16), resolution 1K/2K/4K, background
- เลือกรุ่นได้ด้วยพารามิเตอร์ `model` (`gpt-image-2` | `gpt-image-1.5`) เก็บรุ่น 1.5 ไว้
  ให้ใช้กับงานเก่า และเผื่อผลลัพธ์ต่างกัน
- ตรวจกฎของ KIE ก่อนส่งงาน (ใช้ทั้ง generate และ edit):
  - `auto` ใช้ได้กับ 1K เท่านั้น
  - 2K/4K ใช้ไม่ได้กับ 5:4, 4:5, 3:1, 1:3, 9:21
  - 1:1 ใช้กับ 4K ไม่ได้
  - `background` ใช้ได้กับ 1K เท่านั้น
  - รุ่น 1.5 รองรับแค่ 1:1, 2:3, 3:2 (ถ้าส่ง `auto` มา แปลงเป็น 3:2 ซึ่งเป็นค่าเริ่มต้นเดิม)
- บันทึกรุ่นที่ใช้จริงลงประวัติ (`generations.model`)

**ไม่อยู่ในขอบเขต:** เปลี่ยน skill ในเครื่อง (`imagegen/`) ไปใช้รุ่นใหม่ ทำแยกได้ภายหลัง

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
| --- | --- | --- |
| A: เปลี่ยนเป็นรุ่น 2 อย่างเดียว | โค้ดน้อยสุด | ทิ้งรุ่น 1.5 และพารามิเตอร์ `quality` ทำให้ client เก่าที่ส่ง `quality` มาเสียหาย |
| B: รุ่น 2 เป็นค่าเริ่มต้น + เลือก 1.5 ได้ | ได้ 9:16 ทันที ไม่ทำให้ client เก่าเสีย และเลือกรุ่นได้ในอนาคต | schema ใหญ่ขึ้น ต้องตรวจกฎแยกตามรุ่น |
| C: เพิ่ม tool ใหม่ `edit_image_v2` แยกต่างหาก | ไม่แตะ tool เดิม | มี tool ซ้ำกัน Claude ต้องเลือกเอง สับสนง่าย |

## ทางที่เลือก

**B** — ค่าเริ่มต้นเปลี่ยนเป็นรุ่น 2 ที่ดีกว่าและรองรับ 9:16 ส่วน `quality` ยังรับได้
(มีผลกับรุ่น 1.5 เท่านั้น) client เดิมจึงไม่พัง

- ค่าเริ่มต้นใหม่: `model: gpt-image-2`, `aspect_ratio: auto`, `resolution: 1K`
- กฎของ KIE เช็กใน schema (`superRefine`) เพื่อให้ Claude ได้ข้อความผิดพลาดชัดเจนทันที
  แทนการรอ KIE ตอบ error กลับมาหลังสร้างงาน
- กฎชุดเดียวกันใช้กับ `generate_image` ด้วย (รุ่นเดียวกัน)

## ความเสี่ยง

- การเช็กกฎทำให้ `generate_image` ที่เคยผ่าน schema แต่ KIE ปฏิเสธ (เช่น `auto` + 2K)
  กลายเป็น error ตั้งแต่ schema ผลลัพธ์เหมือนเดิม (ล้ม) แต่เร็วกว่าและชัดกว่า
- ราคาของรุ่น 2 อาจต่างจากรุ่น 1.5 เครดิตที่ใช้จริงบันทึกลง `generations.credits` อยู่แล้ว

## การทดสอบ

- unit: schema (ค่าเริ่มต้น, กฎแต่ละข้อ, รุ่น 1.5), service ส่งพารามิเตอร์ถูกรุ่นและบันทึกรุ่นลงประวัติ
- ทดสอบจริงบน dev: `edit_image` 9:16 ด้วยรุ่น 2 หนึ่งภาพ (ต้องได้รับอนุญาตใช้เครดิต)
